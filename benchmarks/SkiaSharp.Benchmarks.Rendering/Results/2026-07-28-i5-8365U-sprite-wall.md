# SpriteWall: Graphite's home turf — 28% faster than Ganesh on Vulkan

Windows 11 / Intel Core i5-8365U (Coffee Lake, 4 physical / 8 logical cores) / .NET 10.0.8 / SkiaSharp on-branch build.

## Summary

`SpriteWallScene` draws 2,000 rotated + scaled sprites via a single
`SKCanvas.DrawAtlas` call. It's the pattern 2D game engines,
particle systems, and emoji clouds hammer. Graphite's coalesced
sampler binding + render-pass batching gives it a large,
consistent, non-noise architectural win here.

| Backend | Mean | vs Ganesh |
|---|---:|---:|
| **graphite-vulkan** | **856 μs** | **-28%** ✓✓ |
| graphite-vulkan-parallel | 862 μs | -28% |
| ganesh-vulkan | 1,196 μs | (baseline) |
| ganesh-vulkan-nctx | 1,239 μs | +4% |
| raster | 73,402 μs | +6,038% |

## Why this is the clean win

The earlier full sweep (`2026-07-28-i5-8365U.md`) already surfaced
`DrawAtlas` @ 200 sprites at 15% Graphite advantage. SpriteWall
scales that to 2,000 sprites on a 1024×768 surface. The Graphite
edge widens to 28% — the fixed Graphite advantage dominates once
the batched-quad path has enough instances to amortise its own
setup.

**Parallel-graphite matches sequential graphite** (856 vs 862 μs,
within noise). `DrawAtlas` is one draw call — there's nothing for
the CPU-record parallelism to shorten. Sanity check that the
parallel path isn't adding overhead when there's no CPU record
work to distribute.

**Raster is 85× slower** — 2,000 antialiased rotated sprites on CPU
is the classic "GPU pays off" case. Both GPU backends are within 30%
of each other; raster is off by two orders of magnitude.

## Scene structure

- 128×128 atlas built once at construction time — 16 icon-like
  glyphs (star, heart, gear, arrow, chevron, plus, chat bubble,
  sparkle, hexagon, triangle, diamond, moon, dashed ring, donut,
  ring, circle) drawn white on transparent so per-sprite tint
  colours them at draw time via `SKBlendMode.Modulate`.
- 2,000 (sprite, transform, tint) triples precomputed in the
  constructor from deterministic integer hashes — no clock, no
  RNG, same pixel output every frame.
- Per-frame work is one `Clear` + one `DrawAtlas`. All the
  interesting cost is on the backend's batched-textured-quad path.

Not partitioned — `DrawAtlas` is inherently one draw call.

## Companion findings

The story now has scenes on both sides of the ledger:

- **Graphite architectural wins**: `SpriteWall` (-28%), `DrawAtlas`
  (-15%), `DiagonalLines` (-4%) — batched textured / vector primitives.
- **Graphite CPU-record wins with parallel-recording**: `IconGrid`
  (-20% w/ parallel), `HighDrawCount` — vector-heavy scenes with many
  paint-state changes.
- **Graphite regressions**: `LargeImage` (153× slower, likely a real
  bug), `RRectBlur` (3.8× slower), `SuperellipseBlur` (3× slower),
  `AcrylicSample` (backdrop blur, 6× slower per lavapipe), and the
  text-heavy path where parallel-recording *loses* to sequential
  because of glyph-atlas contention.

Rule of thumb: Graphite is faster when the workload is dominated by
**batched textured quads** and **many independent vector primitives with
different paint state**; slower when it's dominated by **complex filter
chains, glyph rendering, or single very-large image uploads**.
